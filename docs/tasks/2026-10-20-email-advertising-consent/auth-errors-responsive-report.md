# Короткие ошибки авторизации и стабильная форма

21.10.2026, ветка codex/email-advertising-consent. Production/SSH/commit/deploy не затрагивались.

Сообщения сокращены для кода, паролей, телефона, длинного имени, ошибок Яндекса, истёкших ссылок, восстановления и завершения входа. Смысл и следующее действие сохранены; правила валидации, статусы API и бизнес-переходы не менялись.

FormError использует12/16px. Под ошибкой поля резервируется одна строка; прежний межполевой отступ перераспределён, от ошибки до следующего поля остаётся8px. Общая ошибка принадлежит StepForm и имеет место под две строки плюс8px до кнопки. Это общий компонент для входа, регистрации, профиля, активации, восстановления; код имеет отдельный стабильный слот возле OTP. Пустые места не имеют role=alert; role/id появляются только с сообщением. Нет truncation/line-clamp или скрытия текста.

На мобильном добавлен отступ между ошибкой и карточкой преимуществ. При проверке320px найден выход невидимого OTP input на3px из-за increase-width для password-manager badge. В auth CodeStep выбрана штатная стратегия none; one-time-code и обычный ввод/вставка сохранены. Shared primitive не менялся.

## Стабильность при появлении ошибок

До правки две ошибки входа увеличивали высоту формы на63.99px и сдвигали кнопку на32px при центрировании. После правки:

- login-320: изменение высоты 0.019px; положения кнопки относительно формы 0.019px.
- registration: изменение высоты 0.039px; положения кнопки относительно формы 0.039px.
- recovery: изменение высоты 0.010px; положения кнопки относительно формы 0.010px.
- reset: изменение высоты 0.019px; положения кнопки относительно формы 0.019px.
- consents: изменение высоты 0.000px; положения кнопки относительно формы -0.000px.

Все изменения меньше0.1px (субпиксельное округление). Скролл к невалидному полю не считался layout shift; сравнивалась кнопка относительно секции. Серверный неверный пароль также проверен:0px изменения. OTP ошибка:менее0.01px.

Проверены signup email, код неверный/подтверждение, регистрация с четырьмя пустыми полями, recovery email, reset с двумя пустыми паролями, consent с выключенным ПДн. Никакие новые пароли не вводились и не сохранялись. На согласиях оба checkbox были выключены, Continue остановился на клиентской валидации; никаких consent decisions/ordinary sessions не записывалось. Не воспроизводились все реальные внешние SSO/429/потерянные ответы: их сообщения просмотрены в коде, сценарная обработка покрыта существующими unit tests. Activation использует тот же проверенный PasswordFields/StepForm; отдельный новый guest activation здесь не запускался.
