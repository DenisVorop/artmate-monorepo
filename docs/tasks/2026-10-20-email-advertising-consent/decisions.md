- **2026-10-20 · Уточнение референса скриншотами.** Пользователь показал последовательность «телефон → SMS-код → самостоятельный экран согласий» и отметил пустой необязательный рекламный checkbox в основной зоне над «Продолжить», а также предустановленный PD checkbox в списке преимуществ. Это уточняет референс; утверждения о допустимости предустановки для Artmate пользователь не давал. Прежнее предложение агента поставить рекламу на OTP-форму исправлено в design.

- **2026-10-20 · Повторный показ при отсутствии согласия.** По прямому запросу пользователя шаг согласий показывается после каждого успешного входа, если рекламного согласия нет; если все нужные согласия уже даны и действуют, шаг пропускается. Прежнее предложение ограничить шаг новой регистрацией отменено. Рекламный выбор остаётся необязательным: продолжение без него завершает текущий flow, но на следующем входе сервер снова проверяет состояние.

- **2026-10-20 · Подключаемая авторизация и общие согласия.** Пользователь прямо запросил `withAuth` для любой формы/компонента и `useAuth({ onSuccess, onError }) → { onAuth }`, чтобы вызывать общий сценарий после любого действия и продолжать его callbacks после результата. Общие согласия централизуются, произвольный email из формы не считается подтверждённым и не даёт рекламного разрешения. Детальный публичный контракт/состояния предложены в auth-module.md; конкретный rollout бизнес-форм и судьба guest checkout требуют явной карты миграции.

- **2026-10-20 · Полная актуализация плана.** По запросу «ещё раз план обнови» документы пересобраны в единый актуальный вариант: подключаемый Auth — основа, миграция форм зависит от серверной identity/consent защиты, этапы последовательны. Новых продуктовых разрешений на реализацию, guest checkout, предустановку согласий или production этим обновлением не добавлено.

- **2026-10-20 · Вход только после «Продолжить».** Прямое уточнение пользователя: подтверждённая почта ещё не авторизация. Удалена прежняя целевая немедленная выдача сессии после OTP. Выбран ограниченный pending flow и общий server completion, который после финального действия сохраняет решения и выдаёт обычную сессию; затем session query и scoped onSuccess. Закрытие до completion не авторизует. Existing session не разлогинивается. При всех согласиях у нового входа повторный consent screen пропускается, явное «Продолжить» остаётся на auth screen.

- **2026-10-20 · Единый вход и профиль.** Более поздний запрос: одна стартовая форма с почтой; при неизвестном адресе перед согласиями ФИО и телефон. Для существующего аккаунта с данными этот шаг пропускается, недостающие поля собираются отдельно. Целевое решение сайта — passwordless email code; реальные способы входа других приложений автоматически не заменяются.

- **2026-10-20 · Исключение для готового аккаунта.** Прямое позднее уточнение: если email зарегистрирован, данные и согласия уже есть, после подтверждения почты сразу авторизовывать. Это заменяет последнюю фразу предыдущего решения об обязательном «Продолжить» у всех. Если недостающий шаг показан, его завершающее действие по-прежнему требуется. Те же правила после Яндекса.
