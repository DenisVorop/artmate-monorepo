# Подключаемая авторизация и согласия Artmate

Редакция 20.10.2026 с учётом паролей и активации после гостевой покупки. Требования заменяют прежние варианты с отдельным входом по коду. Подробные сценарии — [password-flow.md](./password-flow.md), текущий срез — [progress.md](./progress.md).

## Цель

Один модуль `withAuth(Component)` и `useAuth({ onSuccess, onError }) → { onAuth }` для любой формы или компонента. Он подтверждает пользователя, собирает недостающие данные и применимые согласия, затем возвращает управление инициатору. Вход — по email и паролю либо Яндекс ID; email-регистрация и активация после гостевой покупки создают пароль. Рекламное разрешение относится только к доказанному точному адресу и имеет воспроизводимую историю согласия/отзыва.

## Сценарии

| Состояние                                | Порядок                                                                                                                |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Полноценный email-аккаунт                | Email + пароль → недостающие контакты/согласия → вход; без кода                                                        |
| Всё заполнено и согласия действуют       | Верный пароль / проверенный Яндекс → сразу завершение входа                                                            |
| Новая email-регистрация                  | Email → код → ФИО, телефон, пароль и повтор → согласия → вход                                                          |
| Гостевая покупка, ссылка из письма       | Проверка ссылки → пароль и повтор → недостающие контакты → согласия → вход в существующий аккаунт с заказами; без кода |
| Гостевой покупатель выбирает регистрацию | Email → код → продолжение той же записи, пароль и повтор, недостающие контакты → согласия → вход                       |
| Яндекс ID                                | Проверенный результат → недостающие контакты/согласия → вход; локальный пароль не нужен                                |
| Действующая сессия                       | Fresh server check → недостающие gates либо callback без окна и нового входа                                           |
| Восстановление доступа                   | Общий ответ → ссылка активации для записи без пароля либо восстановления для аккаунта с паролем                        |

Кнопки «Войти по коду» нет. Код подтверждает почту при email-регистрации. Запись User после гостевого заказа не считается завершённой регистрацией и не разрешает доступ к заказам.

## Требования

1. Существующие пароли сохраняются. Password login не запрашивает код. Пароль и повтор обязательны при email-регистрации и активации; несовпадение блокирует продолжение. Яндексу пароль не навязывается.
2. Код/ссылка/провайдер доказывают владение адресом, а не согласие на рекламу. Проверка пароля не записывается как новое OTP-подтверждение. Старой базе не приписываются фиктивные проверки или разрешения.
3. До безопасной identity не раскрывать аккаунт, контакты и заказы. Нет публичного email-exists lookup. Для кодов/ссылок — TTL, лимиты, защита от перебора и повторов. Payment return не подтверждает личность или оплату.
4. Активация сохраняет userId и заказы. Ссылка ведёт в ограниченный flow, без ранней сессии. Если пароль уже существует, ссылка не заменяет его. Дополнительный код после действующей ссылки не нужен.
5. Валидные ФИО/телефон не запрашиваются заново. Телефон контактный, без SMS-проверки/рекламы. Новые данные до применимого основания остаются draft с TTL.
6. При недостающих шагах обычная новая сессия выдаётся только после их завершения. Готовому пользователю не нужен лишний «Продолжить». При показанном шаге согласий completion происходит по его кнопке. Прежняя сессия сохраняется при отмене.
7. Реклама — квадратный, пустой, необязательный checkbox. false завершает текущий вызов, не создаёт grant и не является отзывом. Отдельного подписного письма нет. Без рекламы/после отзыва шаг снова появляется на новом явном onAuth, не от refetch текущего вызова.
8. ПДн — управляемый круглый checkbox, включённый по выбранному UX. Хранить факт принятия и версию формы/документа; не хранить initial_checked/final_checked/submit_action и вымышленные описания действий. Юридический механизм конкретной редакции проверить до реального применения.
9. source — необязательное место получения, без суффикса Context. Полный доступный requestContext сохраняется с происхождением данных, без секретов доступа. IP/UA не удостоверяют личность. PDF/форма хранятся один раз на редакцию.
10. После Яндекса общие gates; OAuth scopes не заменяют согласия Artmate. Exact email и linking проверяются отдельно; default_email не объявляется достаточным proof автоматически.
11. Один host, активный owner и payload. Ровно один terminal callback после confirmed completion и fresh session cache. Auth не выполняет бизнес-mutation. Close/unmount подавляют исходное действие; поздний результат не отдаётся другому owner.
12. Общие согласия убираются из форм только после переноса целей и защиты backend. Оферта заказа, клубные, фото- и партнёрские условия сохраняют своё назначение. Произвольный email формы не становится рекламным адресатом.
13. Светлый дизайн сайта, Comfortaa/Nunito, gradient CTA, маленькие 3D-палитра и success-галочка. Справа одинаковые круглые маркеры, ссылка ПДн только цветом; слева квадратная реклама без дополнительного выделения. Маленький официальный «Я» слева в ряду на четыре позиции.
14. Eye/EyeOff во всех password-полях с доступным именем. Вставка/password managers разрешены. Success — «Вы вошли в Artmate», без сообщения о подписке.
15. Mobile без слипания слов/обрезки/overflow; ПДн до submit. В приложение не переносятся demo panels/routes/adapters, пробные коды, timers и simulated state.

Подтверждённому пользователю после почты и пароля показываются недостающие согласия. Повторное подтверждение почты для рекламы не требуется. Если все согласия действуют — сразу завершение входа. Отдельных сценариев для аккаунтов с миграцией нет.

## Объём

Этапы 10 и 11 отложены по решению пользователя 21.10.2026: рекламную рассылку пока не делаем. Последовательность —8→9→12→13→14; текущая точка продолжения описана в progress. Архив/экспорт/расширенная retention-инфраструктура и gate/queue/SMTP рекламных отправок не входят в текущую приёмку и выпуск. Базовое сохранение согласия, версии документов/формы, source, очищенного requestContext и истории отзыва сохраняется. Рекламная отправка остаётся выключенной; возвращение к 10/11 — отдельная будущая задача.

Сайт, его auth API, guest activation и recovery, profile/consent completion, HOC/hook/host, Яндекс continuation, auth embeds/contact/partner forms, доказательства/отзыв/экспорт/retention, gate будущей рекламной отправки и инфраструктура.

Гостевая покупка сохраняется; обязательный вход до оплаты не вводится. Платёжный сценарий/подтверждение банком/корзина/pricing не переписываются. Admin/affiliate/studio не переводятся на новый UI автоматически; consumers общих endpoints проверяются до изменений. Новые провайдеры, SMS, массовые кампании, автоподписка базы, self-service смена email/слияние аккаунтов и изменение срока сессии не добавляются.
