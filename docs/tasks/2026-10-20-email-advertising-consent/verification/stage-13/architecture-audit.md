Новые сценарии и UI-state находятся в feature `lib`, отдельные mutations — в `model`, `shared/actions/auth` и `shared/actions/consents` содержат transport. Forms Auth/contact/partner используют RHF+zod; DTO mappers находятся в lib. Provider подключается через `withAuth`, имеет установленную структуру, общий host переиспользуется вложенными scopes.
- Owner/callback/cache: `features/auth/lib/auth-flow-coordinator.ts`, `auth-provider/use-auth-request.ts`, `publish-auth-session.ts`, contact/partner state hooks и promo provider проверены на captured payload, single owner, busy/cancel/unmount/epoch guards, recovery прежней операции вместо повторного решения и публикацию session до business callback. Promo retry ждёт новую identity и сверяет cart/signature/code. Guest checkout не вызывает обязательный Auth.
- Subscription: `entities/email-subscription` имеет owner key, fresh focus/mount reads и late cancellation guard. `features/email-subscription-settings/model/use-revoke-subscription.ts` отменяет предшествующие reads, проверяет текущего owner и версию перед cache publication. Настройки не трактуют unchecked advertising + successful Auth как подписку; отзыв идёт напрямую. Новый entity cache очищается в Auth publication/logout.
- Backend: `auth/completion.service.ts` записывает durable Consents/Users commands и ожидает их receipts. Consents handler владеет permission/state/events, Users handler — profile/User. `CompletionAccountStore` устанавливает credential/provider binding только в Auth final transaction; pending capability не становится обычной session. `SiteActionGuard` проверяет current Users publication и реальный published acceptance/FK, actor берёт из verified session; ad opt-in не требуется для contact/partner.
- Flows: password/SESSION не требуют OTP; регистрационный код сам не завершает login; registration/activation требуют password+confirm и недостающие контакты; User/order binding не заменяется. Recovery использует существующий activation/reset сценарий, без раннего session/grant. Yandex policy доверяет exact email authenticated exchange по прямому решению пользователя, без отдельного кода/пароля; state/PKCE/browser binding и authoritative result сохраняются. Existing password не перезаписывается provider linking.

Оставшиеся role-bound `/auth/admin/login` и `/auth/affiliate/login` имеют самостоятельных consumers и role checks. Auth demo/test adapters/routes в новом модуле не обнаружены. CheckoutPreview существует уже в HEAD и не добавлен этой задачей; его не трактовал как новый auth demo defect.
- Unsubscribe: `consents/email-advertising.controller.ts`, service/token issuer, `common/csrf.middleware.ts`, frontend unsubscribe state/mutation проверены. GET/HEAD public unsubscribe не отзывают согласие; human confirm — POST с обычным CSRF; RFC8058 exemption ограничено точным POST route и стандартным form content type. Capabilities random/hash-only, revoke-only, без session/profile/grant доступа. Repeated off не создаёт grant/revoke дублей; recipient lock и publication revision закрывают поздние grants. Старые ссылки после regrant работают согласно принятому контракту.

Next history очищается до human POST, capability остаётся только transient mounted memory, mutation variables очищаются. `RequestEvidenceCapture`, `RequestEvidenceProxyHeaders`, `TrustedProxyEvidence` редактируют auth/cookie/token/query и URL-bearing headers; optional evidence не выключает отзыв при отсутствии proxy key. Визуальный рендер всех страниц и актуальность согласованной юридической редакции этим read-only review не подтверждались.

Дополнительных actionable source defects в этой delta не выявлено:

- Внешний `mutateAsync(input)` контракт и DTO не изменились; внутренний `perform()` получает void, поэтому MutationCache variables не должны содержать secret input. Request ref читается в локальный input перед первым await, остаётся доступен для исходного in-flight запроса и очищается вместе с observer reset в finally. Ref guard не даёт параллельному запросу заменить input. gcTime0 сохраняет удаление detached mutation после settlement.
- Existing callbacks остаются на mutation options; они получают response/error как прежде, а отсутствие variables не меняет их объявленный контракт. Auth provider и Yandex callback используют существующие mutateAsync public names. Публикацией session/owner callback по-прежнему управляет coordinator; новые hook wrappers не обходят его отмену/epoch guard.
- Reset capability фиксируется для текущего mounted document, поэтому clean RSC props `token:undefined` не теряют действующую ссылку и парольную форму. History очищается null state + router replace до submit. UI использует hasToken, после подтверждённого `{ok:true}` capability очищается и success не зависит от исходного query prop. Duplicate submit guard, mounted guard, required acknowledgement и safe error сохранены. Новый document на чистом URL корректно не получает старую capability.
- Code step меняет только min-height двух кнопок, не handler/disabled/OTP контракт.
- Новые тесты проверяют pending и settled MutationCache, duplicate calls/callback preservation, cleanup-triggered rerender, reset acknowledgement/retry и unmount. Они не заменяют actual Next browser проверку истории и жизненного цикла.
