# Макеты и визуальная спецификация

Текущий кликабельный образец: [mockups/auth-password-flow.html](./mockups/auth-password-flow.html). Он включает password login, регистрацию, восстановление и активацию после гостевой покупки; открывается как после условного перехода по действующей activation-ссылке. Сценарии реализации — [password-flow.md](./password-flow.md), текущий статус — [progress.md](./progress.md).

Это HTML-фрагмент для беседы; для браузера нужен preview wrapper. Изображения встроены. Исходник, переносимые ассеты и SHA-256 — рядом, в [manifest.json](./mockups/manifest.json). Выбор состояния аккаунта через host Tweak — настройка прототипа; продуктовая панель/route/adapters из него не копируются.

Ранние [auth-flow.html](./mockups/auth-flow.html) и [auth-success.html](./mockups/auth-success.html) — исторические passwordless варианты и образцы дизайна. Их OTP-вход не является целевым поведением, старые байты/хеши не переписываются.

## Экраны

| Экран                | Поля/действия                                                                   | Переход                                                      |
| -------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Вход                 | Email, пароль, глаз, «Войти», recovery/signup, маленький «Я»                    | Без кода: missing profile/consents либо success              |
| Email-регистрация    | Email, «Получить код»                                                           | Регистрационное подтверждение                                |
| Код                  | 6 цифр, email, resend/change email                                              | Регистрация; не альтернативный вход                          |
| Регистрация          | ФИО, телефон, пароль и повтор, глаза                                            | Совпадение паролей → согласия                                |
| Гостевая активация   | «Завершите регистрацию», почта уже подтверждена ссылкой, пароль и повтор, глаза | Согласия; без повторного кода/известных контактов            |
| Недостающие контакты | Предзаполненные известные ФИО/телефон                                           | Согласия либо completion при готовности                      |
| Согласия             | Квадратная пустая реклама слева, управляемые ПДн default true справа            | «Продолжить», включая отсутствие рекламы                     |
| Яндекс pending       | Короткое ожидание                                                               | Недостающие данные/согласия либо success, без local password |
| Recovery             | Email, общий ответ о восстановлении доступа                                     | В продукте activation либо reset в зависимости от credential |
| Успех                | 3D-галочка, «Вы вошли в Artmate»                                                | Не дополнительный обязательный клик                          |

В прототипе основные состояния аккаунта выбираются host control: guest activation, есть профиль без рекламы, всё готово, неполные контакты, новый аккаунт. Примерные значения и имитация provider не доказывают реальное server identity/consent. Проверки сложных race/invalid link и guest signup collision относятся к runtime, не считаются покрытыми этим happy path.

## Внешний вид

- Светлая тема сайта независимо от темы среды. Comfortaa — заголовки, Nunito — остальное, существующий логотип Artmate и rose/peach gradient CTA.
- Две колонки desktop, одна mobile: main → benefits/ПДн → основное действие. Естественные переносы с настоящими пробелами; скрытый br не склеивает слова.
- Палитра 64 px в правом блоке, success-галочка 64 px над heading. Маленькие прозрачные 3D assets в цветах сайта; mobile допускает палитру 48 px как в макете.
- Справа круглые маркеры одного размера/цвета, включая настоящий управляемый checkbox ПДн. Ссылка ПДн только цветом без подчёркивания. Статичные преимущества не интерактивны.
- Слева квадратная unchecked optional-реклама над Continue. Без отдельного визуального акцента/подписей «по желанию» и «Можно выбрать…». Явная подпись рекламного согласия и документ сохраняются.
- Яндекс: официальный цветной знак 40 px в target 44 px, первая позиция из четырёх с gap 12 px. Пустые/фиктивные провайдеры не рисуются.
- Password visibility — Eye/EyeOff, не текст «Показать/Скрыть»; доступные имена, aria-pressed, keyboard focus, target около 44 px. Повтор пароля имеет собственный toggle.
- Success без текста о наличии/отсутствии подписки. Документ в новой вкладке сохраняет форму и не переключает checkbox.

## Границы и проверка

Макет не отправляет письма, не проверяет реальные пароли/коды/ссылки, не создаёт аккаунты/сессии/подписки/заказы и не собирает evidence. Локальные simulated flags/fixture email/таймер Яндекса в приложение не переносятся; в host state нет введённых паролей, кода, ФИО или телефона.

Результаты прежних проверок и статус реализации — только progress. При реализации проверить все шаги на 320/360/390/430 px и desktop, длинные адреса/ссылки, доступность, mobile порядок ПДн до submit, отсутствие nested form, сохранение caller values. Успех интерактивного мока не заменяет browser QA продукта или server security tests.
