# Запуск тестов API

`yarn workspace api test` сначала генерирует Prisma Client и один раз проверяет
типы исходников и всех тестов через `tsconfig.test.json`. Затем запускает тесты
через `ts-node/register/transpile-only`: повторной проверки типов в каждом из
тестовых процессов нет. Проверка типов не отключена и её ошибка прерывает запуск.

`scripts/test.mjs` находит все `test/*.spec.ts` без ручного списка:

- обычные тесты и миграции на изолированном PGlite — максимум два файла параллельно;
- `*.postgres.spec.ts` — отдельно и последовательно, поскольку могут использовать
  одну тестовую БД. Их прежние opt-in переменные и проверки безопасности сохранены.

Новые тесты с общей PostgreSQL-базой должны иметь суффикс `.postgres.spec.ts`.
Для остальных тестов нужны отдельные временные каталоги, собственный PGlite и
динамический порт (`listen(0)`), а не общие файлы или фиксированные порты.

В CI Turborepo запускается с `--log-order=stream --output-logs=full`, чтобы
показывать прогресс до завершения всего workspace. Для ручного запуска отдельного
тестового файла через transpile-only сначала выполнить `yarn workspace api
check-types:test`. Старые отдельные команды PostgreSQL сохраняют проверку типов
в ts-node и последовательное выполнение.
