# Постепенный запуск цифрового просмотра

Опубликованный полноценный оригинал включает новый просмотр на прежнем адресе картинки. До импорта картинка остаётся доступной через текущую редакцию. Оригиналы используются в миниатюрах, SEO и сравнении работ пользователей. Artmate выбирается внутри нового просмотра по умолчанию.

Импорт не меняет ID картинок, опубликованные редакции, фотографии и сохранённые цвета работ, составы альбомов, даты первой публикации и награды. Он добавляет оригинал и переносит текущий цветной образец/назначения в вариант Artmate. Прежние таблицы нужны до завершения постепенного перехода.

## Подготовка на локальной машине

1. `python3 apps/api/scripts/prepare-coloring-originals.py --collection cifrovaya-raskraska-cvety=/absolute/цветы_оригинал.zip --output /absolute/sources`.
   Повторите `--collection` для остальных архивов. Нужен production slug, не название папки. Проверяются 25 PNG/SVG-пар, размеры, CRC и точные цвета палитры; существующая папка результата не перезаписывается.
2. Сохраните публичные detail-ответы картинок выбранных альбомов в JSON-массив. Подготовитель не читает секреты и не пишет на сервер.
3. `yarn workspace api prepare:coloring-originals --sources /absolute/sources --snapshot /absolute/published.json --output /absolute/bundle --api https://api.artmate.ru --cache /absolute/contours`.
   Номера определяются сопоставлением контура с публичным изображением и уникальным результатом. Имена Frame и приблизительный подбор цветов не используются. Любое неоднозначное совпадение, разный состав обозначений или геометрия останавливает подготовку. В результате получаются WebP, `plan.json` и hash подтверждения.

## Проверка и применение

По умолчанию команда только проверяет пакет и БД в read-only транзакции. Она не создаёт таблицы и не применяет миграции.

```bash
ORIGINAL_IMPORT_DATABASE_URL=postgresql://USER@localhost:5432/ISOLATED_DB \
  yarn workspace api import:coloring-originals --local \
  --plan=/absolute/bundle/plan.json --bundle=/absolute/bundle
```

Для записи дополнительно нужны `--apply --confirm=<planHash>`. Перед вставками повторно сверяются публикация, ID редакции, checksum контура, назначения цветов и текущий каталог Artmate. Существующие оригиналы не перезаписываются; точный повтор того же пакета пропускает уже добавленные записи. Весь пакет фиксируется одной транзакцией. При потере подтверждения COMMIT файлы остаются для безопасного повторного запуска и сверки.

Production-подключение допускается только с явным `--production`; внутри контейнера используется существующий `DATABASE_URL`, без `.env` загрузки и печати credentials. В production-образе запускайте скомпилированный CLI из рабочего каталога API: `node dist/colorings/import-originals.js --production --plan=/absolute/bundle/plan.json --bundle=/absolute/bundle`. По умолчанию это проверка; `--apply --confirm=<planHash>` добавляются только для согласованной записи. `ORIGINAL_IMPORT_DATABASE_URL` — локальная переменная отдельного инструмента, новой runtime-переменной для приложения или deploy не требуется. До production нужны проверка текущей базы, backup и отдельное разрешение на SSH/импорт. Не запускайте apply автоматически в deploy: исходные архивы и hash пакета относятся к конкретным данным.

Пакетные файлы не включаются в Git. После завершения перехода всех тематик прежнюю реализацию нужно убрать отдельным согласованным переносом зависимостей.
