# Artmate Studio — проекты раскрасок

Отдельная приватная студия на `studio.artmate.ru`: Next.js в `apps/studio`, Python API,
SQLite и один worker. Студия имеет общий пароль и общее пространство проектов; существующие
учётные записи, раскраски, каталоги и база данных Artmate не используются. Геометрия строится алгоритмически; локальная обученная модель помогает защищать черты лица.

## Работа с книгой

1. Создайте именованный проект. Его постоянный адрес — `/projects/<uuid>`.
2. Выберите сразу несколько изображений (например, 25). Клиент загружает их по одному;
   каждый успешно загруженный исходник сохраняется сразу. Можно остановить загрузку.
   Закрытие вкладки прерывает ещё не законченные загрузки.
3. Задайте общие параметры: цвета, минимальную площадь, размер символов и первый номер.
   У любой страницы можно отдельно переопределить каждый параметр обработки.
4. «Обработать все» ставит в очередь страницы без актуального результата. Уже обработанные
   с такими же параметрами и активные задания пропускаются. «Пересчитать все» принудительно
   создаёт новые версии. Есть отдельные пересчёт/отмена страницы и остановка всей очереди.
5. Первый успешный результат страницы сохраняется автоматически и бессрочно. Последующие
   версии доступны для проверки; «Принять новую версию» или «Принять готовые версии» заменяет
   сохранённый результат. Во время пересчёта старый остаётся доступен.
6. «Скачать проект» выдаёт ZIP из всех сохранённых страниц: контуры/цвет, SVG/PNG. В архиве
   ровно один выбранный файл на страницу, с именами `page-001.svg` и т. п. Пока хотя бы у одной
   страницы нет результата, полный экспорт недоступен. Отдельный SVG можно скачать из превью.

Проект, исходники и принятые результаты **не удаляются по возрасту**. Можно вернуться по ссылке
после входа, добавить страницы, изменить порядок и параметры. Удаление страницы или проекта
удаляет связанные файлы; во время загрузки/обработки/скачивания оно блокируется.
Ошибка одной картинки не останавливает остальные. Закрытие браузера не останавливает серверную
очередь. После перезапуска worker незавершённое задание повторяется один раз; при повторном
аварийном завершении становится ошибкой, чтобы одна проблемная картинка не зациклила очередь.

## Параметры печати

- Цвета 2–35, включая белые оттенки; фактическая палитра может быть меньше на простых исходниках.
  Белые не входят в легенду. У согласованного корги 20 цветов дают 19 красок и белый.
- Минимальная площадь — **мм²** в конечном печатном размере, произвольная форма детали.
- Искусственная сетка включена по умолчанию. При минимуме 5 мм² целевая площадь ячейки — 20 мм².
  Генератор пробует разделить области больше 30 мм². Сетку можно выключить в настройках
  проекта или страницы. Изменение применяется при следующем запуске обработки.
- Символы — один размер в CSS px, ArialMT из `fonts/Arial/arialmt.ttf`. На горизонтальных
  рисунках поворачиваются вместе с картинкой на −90°. Палитра сохраняет обычную ориентацию.
- Лист 612.28 × 858.9 CSS px, 96 dpi, с согласованными полями и палитрой.
- Контуры/символы `#898989`; группировка палитры в OKLCH до назначения `1–9, A–Z`.
  Белые/близкие к белому области не нумеруются и не дробятся для размещения номера.
- Начальные настройки книги: 20 цветов, 3.5 мм², 5.16 px, первый номер 1.

Изменение порядка и первого номера не векторизует изображения заново. На скачивании/просмотре
пересобираются только номер и палитра; кривые рисунка и символы областей сохраняются. PNG при
изменении номера растеризуется из обновлённого SVG. Палитра каждой страницы самостоятельна.

## Защита мелких деталей

Обычные контуры подгоняются в два этапа. Сначала строятся подробные общие границы,
затем сглаживаются переходы между кривыми. Устойчивые острые углы и общие узлы сохраняются.
Для границ готовых тонких деталей остаются проверенные кривые. После сглаживания
генератор проверяет пересечения, покрытие и минимальную площадь областей.

Новые расчёты используют `coloring-delivery-v21-denser-paint-cells`. Перед упрощением локальная модель
`hysts/anime-face-detector` (YOLOv3 + HRNetV2, готовые веса 2021 года) находит аниме-лица
и 28 ориентиров. Дообучения и внешних запросов при обработке нет. Геометрия извлекается
из исходника; модель задаёт только зоны внимания для глаз, носа и рта.

Защита отдельной зоны включается при достаточной оценке ориентиров и проверке их размеров
и положения. Обнаруженного прямоугольника лица недостаточно. Если исходный ракурс не дал лица, детектор проверяет ещё шесть поворотов изображения.
Профиль допускается только при согласии минимум двух ракурсов, оценке лучшего лица
не ниже 0.95 и уверенном ориентире носа. Повороты служат только распознаванию;
координаты возвращаются к исходнику, само изображение и печатные символы не вращаются.
Дополнительные ракурсы используют те же веса и добавляют время только при пропуске лица.
В таком профиле локальная группировка цветов сохраняет небольшие цветовые области
глаза и губ, даже когда тёмный штрих соединён с длинной линией лица. Ориентиры глаза
и рта не подменяются предположительными координатами. Сохраняются исходные формы,
общие лимиты количества/покрытия и пользовательская палитра.
Закрытые, маленькие и не подтверждённые профили могут остаться без защиты. Для
изображений без принятых подсказок сохраняется прежняя обработка контраста. Поддержка реалистичных лиц и морд животных этой
моделью не заявляется. Ложные срабатывания возможны, нужна проверка на новых стилях.

Дополнительно без распознавания животного отбираются тонкие тёмные штрихи, например усы.
Контраст проверяется поперёк линии с двух сторон, поэтому переход между цветами фона
сам по себе не разрывает защиту. Для этой группы допускаются длинные ветвящиеся штрихи
до 45 мм, с площадью до 40 мм² и максимальной толщиной 1.2 мм до сглаживания.
Края широких тёмных пятен и плотная повторяющаяся текстура отбрасываются.
Дополнительный отбор штрихов исключает насыщенные цветные контуры с недостаточно тёмным
ядром: такие границы остаются обычными цветовыми областями. Это уменьшает риск появления
узких фрагментов без места для номера между готовыми деталями. Это консервативная эвристика, а не гарантия распознавания всех штрихов.
Цвет определяется по тёмной сердцевине исходного штриха и затем сопоставляется палитре.
Новые штрихи не добавляют резервы цветовых акцентов соседних предметов.
Если большая часть ранее найденного обычного тёмного фрагмента подтверждается длинным
штрихом, его цвет уточняется по той же сердцевине. Белые и модельные детали не перекрашиваются.
Компактные детали и блики имеют приоритет; штрихи используют остаток общего бюджета
80 деталей / 0.8% пикселей. Поэтому сохранение каждого уса на произвольном изображении
не гарантируется. Новые штрихи проходят общую сетку. Решение о готовой заливке
принимается по итоговой геометрии при нумерации.

В подтверждённых зонах допускается более слабый контраст и неоднородное окружение; такие
кандидаты получают приоритет внутри общего бюджета деталей. За пределами зон действуют
прежние ограничения по контрасту, форме и плотности похожих деталей. Модель не назначает
цвета: палитра строится существующим алгоритмом в пределах выбранного числа оттенков.

Отобранные области печатаются с готовой заливкой цвета палитры и без обозначения в обоих
вариантах SVG/PNG. Белые блики остаются белыми. Редкие локальные цветовые акценты рядом с
защищёнными штрихами получают резерв в палитре в пределах выбранного числа цветов.
Палитра затем сортируется и получает символы в прежнем порядке.

Порог пользователя в мм² относится к **областям для раскрашивания**. Для готовых деталей
допускается меньшая площадь. Они не делятся и сглаживаются с меньшим отклонением.
Готовая цветная деталь может присоединиться к соседней области того же цвета,
если в объединённой области помещается символ. Для модельных черт лица
это происходит после цветовой коррекции, чтобы не перекрасить деталь.
Соседние области и символы учитывают отверстия в общей векторной сетке.
У белых и близких к белому областей, включая готовые блики, сохраняется внешний контур.
Внутри них не добавляются новые разделители и номера; швы между соприкасающимися
белыми фрагментами одного цвета не печатаются. Контур виден и на границе с
цветной готовой деталью: заливки рисуются раньше линий. Цветным готовым штрихам
серую обводку не добавляем, чтобы не закрывать тонкие детали.

Начальная политика ограничивает отбор 80 деталями и 0.8% пикселей листа. До построения кривых
отбрасываются отдельные пятна меньше 0.12 мм² и кандидаты без толщины 0.18 мм; после сглаживания
аналитическая площадь может быть меньше. Это инженерные ограничения, требующие проверки
на печатной пробе, а не универсальная гарантия типографии. Промежуточные маски живут только
в памяти. Итоговый отчёт хранит версию политики, число готовых деталей и их минимальную площадь;
`actual_min_area_mm2` относится к областям для раскрашивания.

После обновления алгоритма прежние результаты остаются принятыми и доступными. «Обработать все»
предложит пересчёт старых версий, новые результаты принимаются обычным способом.

## Локальные модели

`scripts/prepare_models.py` один раз скачивает две модели с закреплёнными revisions,
размерами и SHA-256 из `details/assets/face-models.json`. Файлы занимают около **272 МиБ**,
не зависят от числа проектов, игнорируются Git и включаются в устанавливаемый wheel.
Docker и CI выполняют подготовку перед сборкой пакета; runtime не скачивает файлы.
При повреждении/отсутствии моделей расчёт завершается явной ошибкой.

Распознавание выполняется на CPU в отдельном дочернем процессе с таймаутом 45 секунд.
Он завершается до векторизации, не получает секреты студии, не сохраняет исходник/маски,
отсекает неуверенные обнаружения до расчёта ориентиров и обрабатывает не более 8 лиц.
При отмене worker завершает всю группу процессов; при потере родителя процесс модели
сам завершает работу. В production весь worker, включая модель, остаётся без сети.
Для Linux в lock-файле закреплены CPU-сборки PyTorch; CUDA не устанавливается.

Для исходного ракурса на локальном Mac arm64 при проверке: примерно 4–6 секунд с запуском процесса и загрузкой
модели, около 0.35 секунды собственно распознавания после загрузки; пик модели около
890 МиБ. Это замеры разработки, скорость и память на VPS требуют отдельной проверки.
Ограничение worker 2 ГиБ сохранено; одновременной векторизации нескольких страниц нет.

Модель и её веса опубликованы автором под MIT:
[детектор](https://huggingface.co/hysts/anime-face-detector-yolov3),
[ориентиры](https://huggingface.co/hysts/anime-face-detector-hrnetv2).
Уведомление лицензии включено в пакет. Зависимости сохраняют собственные лицензии.
Отчёт `face_protection` хранит версию модели, число найденных/использованных лиц,
зон внимания, подтверждённых профилей и отобранных деталей. Промежуточные изображения не добавляются.

## Лимиты и хранение

| Параметр | Значение по умолчанию |
| --- | --- |
| Проекты / страницы в одном проекте | 100 / 100 |
| Вся очередь студии | 500 заданий, один worker и один расчёт одновременно |
| Исходник | 25 МиБ, 40 млн пикселей, статический PNG/JPEG/WebP |
| Один результат | 100 МиБ |
| Общий бюджет исходников и результатов с резервами | 2048 МиБ |
| Временная новая версия | 1 час после завершения |
| Незавершённая загрузка после аварии | очищается через 5 минут |
| Таймаут расчёта | 600 секунд |

Источник записывается один раз на страницу; задания ссылаются на него. В очереди хранятся
только параметры и ссылки. 100 МиБ резервируются при взятии очередной задачи в работу,
поэтому 25 страниц не требуют сразу 2.5 ГиБ резервов. После успеха учитывается фактический
размер. При нехватке места очередь ждёт освобождения диска, сохраняя все ожидающие задания.
API заранее резервирует место для постоянного исходника; временный HTTP spool ограничен
25 МиБ и удаляется после запроса. Одновременно загружается одно изображение на API.

У страницы одна принятая версия и максимум одна актуальная новая версия для просмотра.
Старые временные результаты истекают при следующем запуске, предыдущая принятая — после
явного принятия замены. Worker очищает их между заданиями и в ожидании. Действующие выгрузки
защищены lease с продлением во время потоковой передачи архива. Для очистки нужен worker.

Production: worker 2 CPU / 2 ГиБ RAM, API 0.5 CPU / 512 МиБ, интерфейс 1 CPU / 512 МиБ.
Журналы каждого нового контейнера: максимум 3 × 10 МиБ. SQLite/WAL, логи и временные буферы
не входят в квоту артефактов — на томе необходим запас. Архив не сохраняется на диске, в памяти
находится одна экспортируемая страница; тяжёлые экспорты в API сериализованы.

Каждый расчёт сохраняет только `page.svg`, `colored-page.svg`, `page.png`, `colored-page.png`,
`result.json`, `manifest.json`. Промежуточные этапы и бесконечная история отсутствуют. Manifest
записывается последним, все суммы и качество проверяются перед публикацией результата.
В отчёте остаются параметры и версия алгоритма для будущего пересчёта. Старые исследовательские
outputs, фотографии и кэши в приложение не перенесены.

## Локальный запуск

Из `services/coloring`, Python 3.13:

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python scripts/prepare_models.py
.venv/bin/python -m pip install --no-deps --no-build-isolation -e .
.venv/bin/coloring-password
```

Последняя команда интерактивно получает пароль и печатает хеш. В терминалах API и worker
задайте одинаковые переменные (`.env` приложение само не читает):

```bash
export COLORING_PUBLIC_URL=http://localhost:3005
export COLORING_DATA_DIR=/absolute/path/to/private-studio-data
export COLORING_PASSWORD_HASH='полный-хеш-из-coloring-password'
.venv/bin/coloring-api
```

Во втором терминале: `.venv/bin/coloring-worker`. Из корня монорепозитория, Node из `.nvmrc`:

```bash
yarn install --frozen-lockfile
yarn workspace studio dev
```

Откройте `http://localhost:3005`. Dev proxy направляет `/api/studio` на Python порт 8000.
HttpOnly cookie действует 12 часов, Secure при HTTPS; замена хеша аннулирует сессии.
Прежняя локальная БД автоматически мигрирует: каждый одиночный проект становится книгой
с одной страницей, UUID, исходники и результаты сохраняются. Миграция транзакционная,
односторонняя; перед обновлением существующего тома следует иметь резервную копию.
Перед первым запуском новой версии остановите прежние API и worker, чтобы старые
процессы не обращались к обновлённой схеме БД.

## Развёртывание

Корневой Compose: `studio`, `coloring-api`, `coloring-worker`, отдельный `coloring-data`.
API и worker используют один Python-образ, у worker нет сети. Caddy: `/api/studio/*` в Python,
остальные пути `studio.artmate.ru` в Next.js. Отдельные внешние HTTP-порты не публикуются.
CI/CD собирает и публикует образы `artmate-monorepo-studio` и `artmate-monorepo-coloring` в GHCR.

| Переменная | GitHub Actions | Значение |
| --- | --- | --- |
| COLORING_PASSWORD_HASH | secret, обязательно | Результат coloring-password |
| COLORING_PUBLIC_URL | variable | https://studio.artmate.ru |
| COLORING_STORAGE_MB | variable | 2048 |
| COLORING_PREVIEW_TTL_SECONDS | variable | 3600 |
| COLORING_JOB_TIMEOUT_SECONDS | variable | 600 |

Хеш: `pbkdf2_sha256:600000:<salt>:<digest>`; env.example содержит непригодную для входа заглушку.
`COLORING_DATA_DIR` в Compose равен `/data/studio`. TTL проектов удалён из конфигурации:
проекты постоянные. Нужны secret, DNS A-запись и выпуск обоих образов одного IMAGE_TAG.
Изменение файлов репозитория само по себе не разворачивает VPS и не меняет DNS.
SQLite и локальный том рассчитаны на один хост, несколько workers запрещает flock.
Сохранённые проекты следует включить в backup. Публичных аккаунтов, billing, редактора
геометрии и PDF-книг пока нет.

## CLI и проверки

Одноразовый CLI сохраняет прежний контракт и не имеет TTL:

```bash
.venv/bin/coloring-generate /absolute/path/image.jpg --output data/results/job-001 \
  --colors 20 --min-area-mm2 3.5 --font-size-px 5.16 --page-number 1
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
```

## Горизонтальные исходники

Если ширина больше высоты, рисунок при вёрстке поворачивается на −90° вместе с
символами и заливками. Масштаб обработки заранее вычисляется для повёрнутого
вписывания в рамку: площади и размеры символов остаются физическими. Исходный
растр для модели не поворачивается. Палитра и номер страницы сохраняют
обычную ориентацию листа. Экспорт и
перенумерация сохраняют ориентацию рисунка и палитры. Квадратные и вертикальные
исходники не поворачиваются.

## Одноцветные готовые фрагменты

До очистки по площади обычные контрастные фрагменты присоединяются к соприкасающимся
областям того же цвета. Проверка повторяется, если совпадение возникло после
сглаживания или при объединении тесной области для размещения символа.
Объединяются и цепочки таких фрагментов. Касание углом не считается соседством.

`DetailMap.locked_ids` отдельно отмечает подтверждённые тонкие штрихи и модельные
черты лица. В растровой маске 0 означает обычную область, 1 — контрастный фрагмент,
2 — модельную деталь, 3 — подтверждённый штрих. Штрихи сохраняют форму при построении
геометрии. При нумерации штрих можно объединить с одноцветным соседом или
пронумеровать отдельно, если позволяет итоговая форма. Для маленьких насыщенных
цветовых пятен детектор также оценивает контраст с окружением в Lab. Так могут
сохраняться, например, синие глаза на тёмной мордочке.
